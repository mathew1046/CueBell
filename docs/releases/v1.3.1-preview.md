# CueBell 1.3.1 — latency controls and measured benchmarks

## What is new

- Opt-in backend settings for correction-aware alert scheduling, ordered outbound
  delivery, OpenAI reasoning and service tier, prompt/input options, and Gnani
  endpointing experiments.
- Speech-aware spoken-request completion tracks outstanding utterances before
  applying a shorter quiet period.
- Stream shutdown invalidates pending work and cancels processing before provider
  cleanup, preventing a delayed alert after coverage has failed.
- A reproducible benchmark using 24 ElevenLabs speech fixtures in Hindi, Malayalam,
  Tamil, Telugu, Marathi and Indian English: 22 runs and 174 case attempts against
  real Gnani Prisma and OpenAI GPT-6 Luna APIs.

## Measured results and release defaults

The tested Fast/speech-aware setup profile reduced median request-confirmation
time from **10.75 to 6.21 seconds**, with six successful trials in each arm.

Full monitoring validation did **not** establish accuracy-neutral acceleration:
baseline **23 passed / 1 failed / 4 inconclusive**, candidate **22 / 2 / 4** under
the stricter target-and-counter benchmark. Experimental settings remain opt-in;
baseline defaults are retained.

These measurements replay synthetic audio into the backend. They do not measure
phone microphone capture, native notification latency or real-venue accuracy.

Full results, configuration, traces and reproduction instructions:
https://github.com/mathew1046/CueBell/blob/v1.3.1-preview/docs/LATENCY_BENCHMARK_2026-11-13.md
